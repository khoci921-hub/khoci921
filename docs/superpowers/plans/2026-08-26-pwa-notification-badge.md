# PWA FCM Badge & Ikon Notifikasi ASJ Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Memberi setiap perangkat admin/kandidat tanda notifikasi lokal yang jelas tanpa menyimpan status baca atau hitungan notifikasi di server.

**Architecture:** Backend membentuk FCM _data message_ yang hanya membawa `title`, `body`, dan `url`. Sumber handler service worker dipisahkan ke `src/sw-fcm-notification.js`; `scripts/build-js.mts` memasukkannya ke `sw.js` saat build. Service worker menampilkan notifikasi dan mengaktifkan badge lokal bernilai satu, sedangkan `pwa.ts` menghapus badge hanya pada perangkat yang sedang membuka portal.

**Tech Stack:** TypeScript, Vitest, Firebase Cloud Messaging HTTP v1, service worker klasik, Web App Badging API, Node.js/esbuild.

## Global Constraints

- Tidak ada tabel, action API, polling, atau status baca lintas perangkat.
- FCM tetap mengirim ke setiap token perangkat yang terdaftar.
- Payload FCM harus data-only; `message.notification` dan `webpush.notification` tidak boleh dikirim agar service worker mengendalikan satu notifikasi.
- Ikon kartu notifikasi tetap `/icons/icon-192.png`; ikon status adalah `/icons/notification-badge.png` transparan dan monokrom.
- Badging API opsional: kegagalan atau ketiadaan API tidak boleh mencegah notifikasi muncul.
- Semua artefak `sw.js`, `pwa.js`, dan bundel hanya diperbarui melalui `node scripts/build-js.mts`.

```ts
export function buildPushPayload(token: string, title: string, body: string, url = '/') {
  return {
    message: {
      token: String(token),
      data: { title: String(title || ''), body: String(body || ''), url: String(url || '/') },
      webpush: { headers: { Urgency: 'high' } },
    },
  };
}
```

`sendPushNotification()` mengganti objek payload lama dengan pemanggilan helper ini.

- [ ] **Step 3: Write minimal implementation**

```js
export function buildServiceWorkerFcmHandlers() {
  return `// FCM_NOTIFICATION_HANDLER_START
messaging.onBackgroundMessage(function (payload) {
  var data = (payload && payload.data) || {};
  var options = { body: String(data.body || ''), icon: '/icons/icon-192.png',
    badge: '/icons/notification-badge.png', data: { url: String(data.url || '/') },
    requireInteraction: true };
  var work = [self.registration.showNotification(String(data.title || 'Notifikasi Baru'), options)];
  if (self.navigator && typeof self.navigator.setAppBadge === 'function') work.push(self.navigator.setAppBadge(1).catch(function () {}));
  return Promise.all(work);
});
// FCM_NOTIFICATION_HANDLER_END`;
}
```

`scripts/build-js.mts` membaca helper tersebut dan mengganti blok handler lama atau region bertanda di `sw.js`. `js/fcm-client.ts` mengambil judul/isi dari `payload.data` dengan fallback kompatibilitas ke `payload.notification`. `pwa.ts` memanggil `navigator.clearAppBadge()` dengan guard pada initial load dan `visibilitychange` saat halaman aktif.

`icons/notification-badge.png` dibuat 96×96 piksel, alpha transparan, dengan emblem ASJ putih saja agar Android merender bentuk logo, bukan kotak putih penuh.
